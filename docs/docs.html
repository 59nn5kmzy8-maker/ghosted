ghosted_ / Docs / Overview

Set up once. Then forget it.

ghosted_ runs through Claude Code hooks on every prompt. You never call it; the commands below are only for tuning.

In plain words. Everything in your Claude Code chat is the context, and Claude re-reads all of it on every message. You pay for that in tokens, or it counts toward your Pro/Max limit. When you finish one job and start another, the old chat keeps being re-read for nothing. ghosted_ notices the switch, saves the old chat and starts you fresh.

It does three things on its own. When a prompt starts a new task, it archives the old conversation, clears the context and starts your prompt with up to five facts carried over. While you're away, it keeps the prompt cache warm so coming back doesn't rewrite it. And it keeps terminal answers short. Everything that goes wrong fails open: your prompt goes through as if ghosted_ weren't installed.

Install

First, check Node.js: run node -v. If it says “command not found”, install Node from nodejs.org. ghosted_ runs on Node, and Claude Code's own installer doesn't include it. Cache warming and the terminal bridge also use python3 on macOS and Linux, which most Macs and Linux machines already have.

$ claude plugin marketplace add giovanbelle/ghosted
$ claude plugin install ghosted@ghosted

Restart Claude Code. It asks four setup questions: press Enter on each to keep the defaults. Then work as usual. The first time you start a new task you'll see a line from ghosted_, and your task starts by itself. Run /ghosted-stats any time to see what it saved.

Cache warming

Claude's prompt cache expires after 5 minutes, or after 1 hour on most subscriptions. After a longer break, your next message writes the whole context to the cache again, at 1.25× or 2× the input price. A cache read costs 0.1×.

While your session is idle, ghosted_ runs a hidden copy of it just before the cache expires and sends one short message, which reads the context from the cache and keeps it alive. The copy is deleted right after; your conversation is never touched. One ping read 191,089 tokens from the cache and wrote 372.

It stops when you're back, when Claude Code closes, after the window you set, if a ping ever misses the cache, and before the pings cost half of the rewrite they prevent. It only pays off if you return to that session.

Some terminals, like VS Code's, Ghostty and Alacritty, give outside programs no way to type into them. Run /ghosted setup once: it adds a small claude function to your shell config that runs Claude Code through ghosted_'s own pass-through terminal layer, so ghosted_ can type for you there too. Everything you type and see is unchanged. /ghosted setup off removes it.

Uninstall

claude plugin uninstall ghosted@ghosted

To delete its archives and stats, remove ~/.claude/plugins/data/ghosted-ghosted. Nothing is stored anywhere else.

FAQ

Will it clear something I still needed?

Rarely: 0 wrong switches in the latest 64 test prompts, and the judge answers “same” when unsure. If it happens, the old chat is archived and /ghosted-recall finds it. Start a prompt with same: to block a switch.

Why clear instead of compact?

A compact summary still carries a lot of old text and costs a model call to write. Clearing with a few carried facts saved 70%; compacting saved 34%.

I already use caveman. Do I need both?

They stack: $3.32 per run with caveman alone, $0.92 with ghosted_ added. ghosted_'s own terse mode steps aside while caveman is active.

Nothing happened after “new task detected”.

Your terminal can't be typed into from outside, or macOS automation permission was declined. Run /clear, then type go; your task comes back. To make it automatic, run /ghosted setup once.
