How it works

Two hooks and one cheap question.

ghosted_ runs inside Claude Code on every prompt. Most prompts pass straight through in about 55ms. Only a likely task switch reaches the judge.

Every arrow down means your prompt goes through untouched.

Task switch on

Above 20k tokens of context, a prompt that starts something new triggers a clean restart.

  • Old chat archived, readable only by you
  • Prompt restored and started automatically
  • Up to 5 facts from the old work carried over

Cache warming on · 2h

Claude's prompt cache expires after a break. Coming back then means writing the whole context to the cache again, at up to 2× the input price. ghosted_ keeps it warm while you're away.

  • A hidden copy of the session sends one short turn just before expiry
  • Measured: 191,089 tokens read from cache, 372 written
  • Stops when you're back, or before it costs half of what it saves
you step away
12:00 your last turn · cache lives 1 hour
12:55 ghosted_ opens a hidden copy of the session
12:55 ping · 191,089 tokens read from cache · 372 written
12:55 hidden copy deleted · your chat untouched
13:50 ping · 191,089 read · cache alive until 14:50
back at 14:20: continue with the tests
cache hit · no full rewrite of 191k tokens

Long runs opt-in

For runs that go on long after their early context went stale. Off by default, because in single runs it cost more than it saved.

  • Set a limit: /ghosted max 250k
  • Past it: stop, /compact, continue
  • /ghosted max off to turn it off
limit 250k

Overrides

One word at the start of a prompt decides for the judge.

  • same: never switch on this prompt
  • new: always switch, no judge
  • /ghosted pause turns everything off
overrides
same: now do the same for the admin page
same: → stays in this task, no judge
⏺ Applying the same change to src/admin
new: plan next week's sprint
new: → switch now, no judge
ghosted: new task detected, clearing first.
